# Repo Skill: AdaptivePlotter

Use this repo-local skill for normal development requests. `AGENTS.md` owns the detailed workflow contract; do not duplicate it here. `blackdog.toml` owns handler setup, validation, and a document-routing catalog. Read only catalog entries relevant to the current task; do not load every routed document by default.

## Workflow

- `$blackdog install or update in this repo`: before this repo-local skill exists, analyze the repo, then run `./.VE/bin/blackdog repo install --project-root .` when missing or `./.VE/bin/blackdog repo update --project-root .` followed by `./.VE/bin/blackdog repo refresh --project-root .` when already installed; finish with `git status --short` and commit or land managed repo changes, or report the checkout as intentionally dirty.
- `$adaptiveplotter do <task-description>`: use only for work outside the episode architecture and migration. If a request mentions or would change the Episode Architecture Vocabulary, Episode Architecture Execution Plan, its ledger/packages/gates, target episode seams, or implementation of that migration, stop this generic path and require exactly one explicit episode command below. The generic path can never authorize an attended-physical or remote-Git episode package. For allowed non-episode work, create the two mode-0600 UTF-8 temporary prompt files required by `AGENTS.md`; keep the exact triggering request in `request_file` and a concise goal, relevant context, constraints, and done condition in `execution_prompt_file`. Run `./.VE/bin/blackdog task begin --project-root . --actor codex --execution-prompt-file "$execution_prompt_file" --prompt-mode skill --request-file "$request_file" --json` directly. Delete `request_file` and `execution_prompt_file` only when the structured `task begin` result contains both a nonempty `execution_prompt_replay_artifact_path` and a nonempty `user_prompt_replay_artifact_path`; otherwise preserve both temporary inputs.
- `$adaptiveplotter audit episode migration`: read [references/episode-migration.md](references/episode-migration.md) completely and perform its read-only reconciliation. Report canonical-`main`, Blackdog, ledger, evidence, dependency, and package-contract state without selecting work, writing a prompt file, starting a task, or changing Git.
- `$adaptiveplotter compile episode package <ID>`: read the focused protocol completely, verify the named package and dependencies read-only, and return its exact execution prompt as a preview. Do not write the preview to the repo or a durable task artifact and do not run `task begin`.
- `$adaptiveplotter execute episode package <ID>`: read the focused protocol completely and execute only that named package through the normal Blackdog workflow. Never infer or auto-select a package. Attended-physical and remote-Git packages require a separate explicit authorization that names that execution class; this generic form cannot authorize them.
- In mutation modes only, make implementation changes in the returned task workspace. Episode audit and compile modes stop before `task begin` and therefore never validate, land, or clean a task.
- After a mutation mode has entered Blackdog, treat every structured result from `task begin`, `task show`, `task recover`, `task cancel`, `task reopen`, `task land`, `task reconcile-landing`, `task close`, and `task cleanup` as follows: its `next_action` is the sole authority regardless of `operation_status`; execute its exact `argv` when `kind=command`; choose only a complete action from `choices` or `alternatives`; stop when `kind=blocked` or `kind=complete`; never infer an action from display text, reason or error prose, summaries, or compatibility recommendations.
- For mutation modes only, validate as required by `AGENTS.md`, then land with `./.VE/bin/blackdog task land --project-root . --summary "$completion_summary" "${validation_args[@]}" --json` using real `NAME=passed|failed|skipped` evidence and a concise human-readable summary.
